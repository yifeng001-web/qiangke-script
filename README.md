# 抢课脚本

基于 Astrwechat 本地消息推送的 Windows 报名助手。监听指定微信群的新消息，识别报名链接或图片二维码，按本地配置填写信息、保存，并在开放时间执行报名。

支持按群和关键词筛选、图片导出等待、断线重连、重复活动去重、控件名称识别及图像标定。运行环境为 **Windows、64 位 Python 3.10+（推荐 3.12）**，首次启动需联网安装依赖。

> 需要先配置 Astrwechat，并根据真实报名页面调整步骤。当前已通过本地协议模拟和 Windows 测试表单验证，尚未验证真实活动报名成功；不保证抢到名额。微信小程序专用入口、登录和验证码需要人工处理或针对实际页面适配。

## 快速开始

1. 在 GitHub 仓库页面选择 **Code → Download ZIP**，解压到普通文件夹。
2. 安装 64 位 Python，安装时勾选 **Add Python to PATH**。
3. 按下一节设置 Astrwechat，然后双击 `启动抢课脚本.bat`。首次启动会创建本目录的 `.venv` 环境、安装依赖，并生成本地 `config.json`。
4. 点击 **编辑本地配置**，填写本人群信息、表单内容和真实页面步骤；保存后点击 **重载配置**、**检查连接**。
5. 先将 `仅预填` 改为 `true` 做试填；确认页面适配后改回 `false`，点击 **开始监听**。

## Astrwechat 设置

自行安装并配置 [Astrwechat](https://github.com/CMKH1337/Astrwechat/releases)。本项目接口适配参考其 **1.5.1** 源码，后续版本若修改接口可能需要更新适配。

先让 Astrwechat 能正常显示本机微信的目标群消息和图片，再开启 **HTTP API 服务**与**消息主动推送**。把实际本机地址和 AccessToken 填入 `config.json`；默认地址为 `http://127.0.0.1:5031`，实际端口以 Astrwechat 设置为准。数据库连接和图片设置在 Astrwechat 内完成，本项目不附带 Astrwechat 程序或数据库。

微信、Astrwechat 和本程序需要同时运行，微信保持在线。监听不要求微信群窗口在前台，最小化后消息和图片是否及时同步取决于微信及 Astrwechat。实际填表时需要可交互的桌面，电脑不要锁屏或睡眠。

**检查连接**会验证 API、群匹配和 SSE 推送接口；这一步不能代替图片导出及真实页面试填。

## 配置说明

公开模板为 [`config.example.json`](config.example.json)，所有个人设置填写在本机 `config.json`。首次启动自动复制模板；也可以手工复制一份并命名为 `config.json`。程序不会覆盖已有本地配置。

JSON 不支持注释；使用英文双引号，末项后不要加逗号。姓名、学号、手机号等写成字符串，保留前导零。模板内“待填写”的内容必须替换。

**配置模板中的步骤只是示例，必须按实际页面调整。** 如果实际页面只有填写和提交，删除“保存信息”，并把“最终报名”的识别文字改成实际按钮文字；如果要先点“我要报名”才能出现表单，在填写前增加一个提前点击步骤。下拉选项、同意条款等可以配置逐个点击，但必须以真实页面为准，不会自动替你选择选项。

| 配置 | 如何填写 |
| --- | --- |
| Astrwechat地址 / AccessToken | 填 Astrwechat 的本机 API 地址和访问令牌。不是微信密码，也不是数据库密钥。 |
| 群名称 / 群ID | 群名必须完全一致。同名群不猜选；推荐填写以 `@chatroom` 结尾的群 ID，填写 ID 后优先用 ID。检查连接成功后会显示该 ID。 |
| 活动关键词 | 如 `["志愿", "讲座"]`；任一词命中最近 10 分钟、最多 12 条目标群消息即可。`[]` 表示不筛选关键词。消息必须在开始监听后收到。 |
| 允许二维码域名 | 如 `["baominggongju.com"]`，允许该域名及其子域名。用于筛选群内链接和二维码，不能填写 `https://`、通配符或路径。页面最终跳转并未进行域名核验。 |
| 页面标题包含 | 默认浏览器窗口标题中需要包含的文字，建议改为实际报名平台或活动标题的独特文字；不能为空。点击“识别当前页”不检查此项，实际操作会检查。 |
| 报名时间 | 留空：优先从通知中的明确“报名时间”解析；解析不到则页面就绪后立即操作。手工填写 `2026-12-01 19:00:00` 时优先用手工值，北京时间。旧时间会立即执行，换活动时记得清空或更新。 |
| 自动读取报名时间 | 支持明确日期和时间，如“报名时间：2026年12月1日晚上19:00”。不猜“今晚七点”“明天”等模糊文字；冲突时间不自动选择。只接受未来 31 天以内或刚过 2 分钟以内的时间。 |
| 智能识别 | 优先用 Windows UI Automation 按名称寻找输入框/按钮。多个同名控件会停止。设 `false` 时完全使用图像标定。 |
| 仅预填 | `true` 时只执行填写步骤，跳过所有点击步骤（包括保存和导航）。适合已进入表单的页面；不会帮你进入需要先点击的下一页。 |
| 成功提示文字 | 真实成功页面的完整提示文字。只有操作后新出现、能被 UIA 读取的文字完全匹配，才报告检测到成功。否则报告“操作已发出，未确认成功”。 |
| 阶段 | `提前` 步骤马上执行；遇到第一个 `到点` 步骤才等待开放时间。所有提前步骤必须放在到点步骤前。只有平台允许提前填写时才能提前保存。 |
| 名称 / 识别文字 | 名称是唯一的本地步骤名，也是标定文件名；识别文字是页面控件的可访问名称，可列多个候选，去掉空格、冒号和常见“必填”后精确匹配。 |
| 内容 | 本人要填写的真实值，只在本地保存。未替换“待填写”时不会开始报名。 |

## 页面适配与标定

1. 先手动打开真实报名页面、完成登录，让报名表单显示出来。脚本通过系统默认浏览器打开二维码链接；先把常用、已登录的浏览器设置为默认浏览器。
2. 点 **识别当前页**，3 秒内切换到报名页。助手只读列出可访问的输入框和按钮名称，把它们填到对应步骤的“识别文字”。不会读取表单值。
3. 不能识别时，在助手下拉框选择步骤，点 **标定所选步骤**。3 秒内切换到报名页，鼠标停在输入框或按钮的点击中心。会截取中心 160×48 区域，保存为 `calibration/步骤名.png`。
4. 标定图必须包含独特文字/边框。大片纯白输入框、外观相同的多个输入框不能可靠区分。若智能识别发现多个同名控件，先缩小识别文字；仍不能解决，可关闭智能识别并为所有步骤标定。
5. 标定后保持屏幕 DPI、浏览器缩放、控件大小一致。支持位置移动，但不支持缩放变形。控件必须位于主屏幕可见区域；程序不会自动滚动找隐藏字段。
6. 文字输入采用 Windows Unicode 批量输入，不借用剪贴板。UIA 可读取值的控件会检查读回结果；图像标定的控件无法核验值，务必先试填。

UIA 无法读取某些小程序/网页控件。若链接只能在微信小程序内打开，需要先在微信内进入真实报名界面，再按该界面适配；**目前没有自动从浏览器跳入任意微信小程序、登录或过验证码的能力**。如果你的平台只能这样打开，本版不能保证从群消息到报名全自动，需补充具体界面后适配入口。

## 日常使用与速度

- 提前启动并登录微信、Astrwechat 和默认浏览器；确认 Astrwechat 图片可用、个人信息正确，电脑时间已同步。
- 点击 **开始监听** 后后台等待，只处理指定群的新消息。检测到允许域名的单个链接，或新图片中的单个有效二维码，会打开页面并按步骤执行。图片等待最多按“图片等待秒”重试。
- 每次运行最多处理一个活动，完成或出错后停止本次任务，需要再次点击开始监听。这样不会继续报名后续不相关活动。
- 原生推送收到事件就处理，图片定位使用原消息 ID，避免同一秒多张图取错。断线自动重连并按消息 ID 去重。Astrwechat 的回放缓存有限（源代码为最多 1000 条、10 分钟）；断线太久或群消息特别多时可能漏消息，不支持保证离线期间完整补齐。
- 填表过程中不要切换窗口或操作鼠标键盘。助手会校验前台窗口、点击位置与控件启用状态；窗口被遮挡或输入读回异常会停止。
- `页面检测间隔毫秒` 是找控件的等待间隔，不是端到端延迟保证。默认 40ms；降低到 10ms 会增加 CPU 使用，不能缩短微信同步、图片导出、网络响应时间。控件树扫描本身也需要时间。
- 能提前识别的到点按钮会预先解析，在开放时刷新位置/启用状态。剩余最后 2ms 短暂自旋，主要等待不占满 CPU。程序不循环轰炸提交接口，也不保证抢到名额。
- 图像标定不能可靠读取按钮禁用状态；图片变灰、倒计时变化可能导致匹配失败。优先使用 UIA，并在按钮开放后的外观下标定备用图。
- 按 **停止** 或 `Ctrl+Alt+F12` 停止；网络及系统可访问性调用正在返回时可能有延迟。关闭助手不会关闭微信或 Astrwechat。

## 去重与故障处理

程序打开报名链接前，把活动链接的 SHA-256 摘要写入 `已尝试活动.json`，避免重启后再次提交。同一个报名工具活动的不同分享参数按同一活动处理。失败或只预填也会保留记录。想重试时，先人工核对是否已报名，停止助手后删除此文件，再让目标群产生新的相关消息；不会自动重新处理启动前的旧二维码。记录最多保留 2000 个活动。

- 连接被拒绝：检查 Astrwechat 已运行、API 端口正确。
- 401/403：检查 AccessToken，以及 HTTP API 和主动推送是否开启。
- 找不到群：检查完整群名，或使用准确群 ID；Astrwechat 必须已同步这个会话。
- 能收到消息但图片失败：先在 Astrwechat 确认该图片能够显示/导出；检查微信自动下载、Astrwechat 图片配置。程序不读取微信密钥。
- 找不到控件：检查页面标题、步骤文字、登录状态、控件是否可见；必要时标定。某些浏览器需要开启辅助功能支持才能暴露完整控件树。
- 已点击但无成功提示：请在平台查看记录，不要仅凭日志“已操作”认定成功。程序不会自动重试提交。

## 文件结构

```text
抢课脚本/
├── README.md              # 使用说明与 GitHub 首页
├── config.example.json    # 公开配置模板，无个人信息
├── 启动抢课脚本.bat       # 双击启动入口
├── bootstrap.py           # 创建环境、安装依赖和启动
├── signup_helper.py       # 界面、配置和报名流程
├── astr_client.py         # Astrwechat 消息与图片接口
├── smart_ui.py            # 按可访问名称定位控件
├── native_input.py        # Windows 鼠标键盘输入
├── requirements.txt       # Python 依赖
├── THIRD_PARTY.md         # 第三方来源说明
└── tests/                 # 本地自动检查
```

运行后生成的 `config.json`、`.venv/`、`calibration/` 和 `已尝试活动.json` 都是各自电脑的本地文件，已在 `.gitignore` 中排除。源码配置入口在 `signup_helper.py:read_config`，群匹配入口在 `astr_client.py:AstrClient.resolve_group`。

## 上传 GitHub 与分享

仓库名称填写 **抢课脚本**，将本文件所在目录的全部项目文件（包括 `.gitignore` 和 `.gitattributes`）上传到仓库根目录。公开仓库只保留空白的 `config.example.json`，朋友下载后在自己的电脑生成并填写 `config.json`。

使用 Git 提交时，忽略规则会排除本地配置和缓存；**GitHub 网页手工上传不会应用本机 `.gitignore`**，不要选中 `config.json`、标定截图、活动记录、虚拟环境或日志。程序也不会替你上传任何文件。

本项目通过本地接口使用 Astrwechat，第三方来源见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 开发与验证

手动安装、启动（也可直接使用启动脚本）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe signup_helper.py
```

运行自动检查：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用本地 HTTP 模拟服务及虚拟资料，不连接真实微信或提交报名。当前包含 SSE 分帧、群和消息过滤、重连去重、延迟图片/二维码、令牌与媒体地址校验、配置生成及保护、Unicode 输入缓冲、图像定位和停止流程检查。

先前的本地真实 Windows 测试表单已验证中文输入与读回、保存一次、到点点击移动后的启用按钮一次，并读取新的成功提示。真实活动仍需要按实际页面完成端到端试用。
